# Lab Tasks
>[!EXAMPLE] - Scenario
>Designing a simplified Online Course Registration System for a university.
>- The system allows Students to register for Courses, each managed by an Instructor.
>- A Student can enrol in multiple, courses, but cannot register for a course that is already full.
>

>[!EXAMPLE] Task 1 - Create a UML Class Diagram
># UML Class Diagram
>Use Visual Paradigm Online, PlantUML, or Draw.io
>## Classes
>- Student
>- Course
>- Instructor
>- Registration
>## Relationships
>- A Student registers for *one or more* Courses.
>- A Course is taught by *exactly one* Instructor.
>- A Course *has many* Registrations.
>- Each Registration *links one Student to one Course*.
>## Attributes
>- Student: id, name, email
>- Course: code, title, capacity
>- Instructor: id, name
>- Registration: date, status

>[!EXAMPLE] Task 2 - Sequence Diagram
>Model the following use case.
>
>A student registers for a course.
>Lifelines for:
>- Student
>- Registration System
>- Course
> Have the methods:
>- selectCourse()
>- checkAvailability()
>- createRegistration()
>- confirmRegistration() 
>

>[!EXAMPLE] Task 3 - Activity Diagram
>Create an *activity diagram* for the Course Registration process:
>1) Student logs in
>2) Selects a course
>3) System checks capacity
>4) If full -> show "Course Full" message
>5) Else -> Register student
>6) Confirmation Displayed

>[!EXAMPLE] Task 4 - Add OCL Constraints
>Write at least **three** OCL expressions:
>1) Invariants
>2) context Course inv: self.capacity > 0
>3) Invariant (Registration rule):
>4) context Course inv: self.registrations->size()<=self.capacity
>5) Precondition (Enroll operation):
>6) context Student::register(C: Course)
>7) pre: c.registrations->size() < c.capacity
>8) post: c.registrations->includes(self)
